# Away mode (product ADR-0065, technical ADR-0038)

The design for the whole feature (trips, paused reminders, learning exclusion, Care banner, plant-sitter flow) is
product ADR-0065. This file records what exists today: **storage, date logic, backup and learning protection
(slice 2, #897), the Settings section, reminder pause and Care banner (slice 3, #898), and the sitter flow
(slice 4, #899: rhythm, Before you leave, confirming and planning visits, sharing), and confirming visits after the
trip and from Settings (slice 5, #900)**.

## Storage (DB 18)
- `away_periods(id, firstDay, lastDay, visitEveryDays?, createdAt)`: `firstDay`/`lastDay` are **inclusive local epoch days**, never instants. No foreign keys, because a trip is global. Past trips are kept.
- `sitter_visits(id, awayPeriodId -> away_periods CASCADE, day, state, createdAt)`, indexed on `awayPeriodId`. `state` is `PLANNED` / `CONFIRMED` / `DID_NOT_HAPPEN`, stored as a String and read with `runCatching` (unknown -> `PLANNED`).
- `sitter_visit_plants(visitId -> sitter_visits CASCADE, plantId -> plants CASCADE, watered?)`, primary key `(visitId, plantId)`, indexed on `plantId`. `watered` is `null` until the visit is confirmed.
- Deleting a trip deletes its visits and their plants; deleting a plant deletes only its visit-plant rows.
- `AwayPeriodDao` is an abstract class so `insertVisitWithPlants`/`replaceVisitPlants` can be `@Transaction`. `AwayPeriodRepository` (lazy singleton in `YaptApplication`) maps entities to `AwayPeriod`/`SitterVisit`/`AwayPeriodWithVisits`; visits come back ordered by day, visit plants by plant id.
- `MIGRATION_17_18` is plain `CREATE TABLE`s matching `18.json`.

## Pure date logic (`domain/away/AwayPeriods.kt`)
- `isAway(date, periods)`; `currentOrUpcoming(periods, today)` (the earliest trip whose last day is not before today).
- **`spansAway(periods, fromMillis, toMillis)` is the one predicate for every away exclusion**: any trip overlaps the inclusive local-day range of the two instants (via `Long.toLocalDate()`); `false` when `toMillis <= fromMillis`. A gap ending on a trip's first day, or starting on its last, spans it.
- `validate(firstDay, lastDay, today, existing, editingId)` returns a sealed `AwayPeriodValidation`, checked in this order: `FirstDayAfterLastDay`, `EndsInThePast` (last day before today), `TooLong` (over `MAX_TRIP_DAYS` = 90 inclusive days), `OverlapsTrip`, `AnotherCurrentOrUpcomingTrip`, else `Valid`. The start may be in the past while the trip is ongoing. `editingId` excludes the edited trip from the conflict checks, so it never conflicts with itself.
- `endEarly(period, today)` ("I'm back"): last day becomes yesterday; `null` (remove the trip) when that is before the first day; never extends a trip.
- `isVisitDayInside` / `visitsOutside(visits, firstDay, lastDay)`: a visit day must lie inside its trip. The caller deletes the visits an edit or `endEarly` strands and reports the count; WATER logs those visits already wrote stay.
- Tests pin the time zone (technical ADR-0013) and include a DST fall-back case.

## Trips UI, reminder pause and Care banner (slice 3, #898)
- **`AwayModeViewModel`** (`ui/screens/away/`, inner `Factory(application, awayPeriodRepository, settingsDataStore)`) serves Settings and the Care banner; `NavGraph` builds one per destination through the same factory. `uiState: StateFlow<AwayModeUiState?>` (`null` while loading) combines `observeAll()` with an injected `dayChange: Flow<LocalDate>` (default `dayChangeTicker()`, technical ADR-0035), so the banner appears and disappears at midnight. `todayProvider` (default `LocalDate.now()`) is what the mutations use; tests inject both, and a non-real ticker (never `advanceUntilIdle()` against the real one).
- **Mutations** return their `Job` (tests `join()` it) and run under one `Mutex`, re-reading the trips with their visits inside it: `saveTrip(first, last, editingId)`, `cancelTrip()` (only a trip that hasn't started), `imBack()` (only a trip that has). Each validates through `AwayPeriods.validate` (an invalid range emits `AwayModeEvent.Rejected`, writes nothing); an edit or I'm back uses `visitsOutside` and `AwayPeriodRepository.updatePeriodAndDeleteVisits` (one `@Transaction`, so the trip and its stranded visits change together) and reports the count as `AwayModeEvent.VisitsRemoved`. **Nothing here writes a plant row** (`AwayModeViewModelTest` pins it).
- **A change to whether *today* is an away day** (compared before/after inside the mutation) calls `onTodaysAwayStateChanged`, which the Factory wires to `ReminderScheduler.runNow()` **only while the in-app notifications switch is on**: `ReminderWorker` checks just the runtime permission, and the daily schedule is cancelled while reminders are off, so an unguarded run would notify against the user's choice. Planning, editing or cancelling an upcoming trip that never touches today does not run it.
- **`domain/away/AwayTripStatus.kt`:** `awayTripStatus(periods, today)` is `None` / `Upcoming(trip)` / `Away(trip)` over `currentOrUpcoming`; `showsBanner(today)` is true while away and from `AWAY_BANNER_LEAD_DAYS` (7, adjust in review) before a trip starts.
- **Settings section** (`AwayModeSettingsSection.kt`, not in `SettingsScreen.kt`): `SettingsScreen` takes an optional `awayModeViewModel` and renders the section between Reminders and Seasonal watering, always visible (away days matter for learning even with notifications off). A status row (`stateDescription` "No trip" / "Trip planned" / "Away"; subtitle "Oct 1 – Oct 21 · reminders resume Oct 22", or "Away now · …") and buttons: **Plan a trip** (none), **Edit dates** + **Cancel trip** (upcoming), **Edit dates** + **I'm back** (away). Cancel and I'm back are immediate with no undo (a trip writes nothing to plants).
- **Date sheet** (`AwayModeDateRangeSheet.kt`): a `ModalBottomSheet` (`skipPartiallyExpanded`) with a Material3 `DateRangePicker`, which returns **UTC-midnight-encoded** millis — convert only through `toDatePickerMillis()` / `datePickerMillisToLocalDate()`, never `toLocalDate()` (same trap as `CareDatePicker.kt`). It accepts any date so each failure can say why; the live `AwayPeriods.validate` result shows as a polite live-region message (`awayValidationText`: one distinct string per `AwayPeriodValidation`, conflict messages name the other trip's dates) and Save is disabled unless `Valid`. A start without an end is a one-day trip.
- **Care banner** (`AwayModeBanner.kt`): see `rules/care-queue.md`. Texts: away "Away until Oct 21 · reminders paused" with **I'm back**; upcoming "Reminders pause on Oct 18 · away until Oct 25" with no action. Slice 4 adds **Plan a sitter visit** (while away) and **Before you leave** (last day at home) here, see below.
- **Date text:** `awayDayText(date, today)` uses `DateFormat.getBestDateTimePattern` ("MMMd", or "yMMMd" when the year differs from today's).
- **Reminders:** `ReminderWorker` gate in `rules/notifications.md`.
- Tests: `AwayTripStatusTest`, `AwayModeViewModelTest`, `AwayModeTextTest`, `ReminderWorkerTest` (the away cases); instrumented `AwayModeSettingsSectionTest`, `AwayModeBannerTest` (incl. the Care screen).

## Sitter flow (slice 4, #899)
No schema change: `AwayPeriod.visitEveryDays`, `sitter_visits` and `sitter_visit_plants` from slice 1 cover everything. **No direct plant-row writes**; the logs go through `QuickLogUseCase`, which may clear a reschedule override or persist adaptive state like any watering. Every due date comes from `TodayQueueAggregator`.

- **Due dates** (`domain/away/SitterDueDates.kt`, internal): `wateringsDueBy(plants, logs, today, horizonEnd, …)` builds a `TodayQueueInput` with a widened `horizonEnd` (#910) and keeps the WATER and WATER_AND_FERTILIZE tasks (a liquid-fertilizer plant is listed for watering only; fertilizer, custom reminders, issues and photos are passed empty). `syntheticWaterLog` dates a simulated watering noon of its day (`LocalDate.toNoonMillis()` in `util/DateUtils.kt`).
- **Rhythm** (`SitterRhythm`): options `4/5/7/10/14`; a rhythm flags a plant when `gap * 2 >= interval * 3` (inclusive). The usual interval comes from `WateringOverviewBuilder` on the trip's first day (so seasonal and dormancy state are that day's); resting (dormant, cadence or suspended), unscheduled, archived and hidden (#915) plants are left out. Recommended = longest option with nothing flagged, else the fewest flagged with the **longest** winning a tie. `lastDayAtHome = firstDay - 1`. `SitterRhythmViewModel` saves only `AwayPeriod.visitEveryDays`; the screen (`Screen.SitterRhythm`) is opened automatically after a **new** trip is saved and from the Settings section.
- **Before you leave** (`BeforeYouLeave.plan`, `BeforeYouLeaveViewModel`, `Screen.BeforeYouLeave`): gap = `visitEveryDays ?: 7`, first visit = today + gap; **Water today** = due `<= today + (gap - 1) / 2` (strictly before halfway, overdue included, ticked), **Check the soil** = due up to the first visit (unticked), the rest "can wait". No simulated waterings (the owner is about to water). Available only when the trip starts tomorrow (`AwayModeUiState.isLastDayAtHome`), else `NotAvailable`. **Log N as watered** calls `QuickLogUseCase.bulkLog(ticked, WATER)`: Plant List's path, no reason prompt, duplicate guard applies, feedback `null` (like "Just my timing").
- **Projection** (`VisitProjector`, pure): at visit day *v*, gap *g*, a plant is listed when due on or before `v + (g - 1) / 2` (= due `<= v` or strictly before `v + g/2`; a tie goes to the next visit). Simulated waterings are fed to the aggregator as WATER logs: every plant due on or before the last day at home (evaluated at `today = lastDayAtHome`, logs up to that day) is watered that day, and every **earlier** visit counts by state (confirmed: only `watered == true`; unconfirmed `PLANNED`: its whole list; `DID_NOT_HAPPEN`: nothing). "Earlier" = `day < v`, plus a same-day visit that isn't `PLANNED`; a same-day `PLANNED` visit is the one being replaced and is ignored, and later visits are ignored. A simulated watering clears an active reschedule when it is at least the plant's newest real WATER (as a real one does). **Missed last time** = `watered == false` at the latest earlier non-`DID_NOT_HAPPEN` visit, only when that visit is `CONFIRMED`. **Longer than usual** = `isLongerThanUsual(g, usualInterval)` for listed plants (dormant cadence interval for a cadence plant). `resting` = the Watering overview's RESTING plants that aren't listed.
- **Summary** (`VisitProjection.summary()`): count, `RoomCount`s (alphabetical, "No room" last), resting count, and the four note lists (missed, longer, no photo, look-alikes = no photo and another listed plant with the same trimmed lowercase name and room).
- **Plan screen** (`PlanVisitViewModel`, `Screen.PlanSitterVisit`): `PlanVisitUiState` is `NoTrip` (no current/upcoming trip, or it ended), `Confirm` or `Plan`; the derivation is the pure `planVisitState` (`PlanVisitState.kt`). Day = Today / Tomorrow / a picked date (`isSelectableVisitDay`, UTC-midnight encoding via `toDatePickerMillis()`), always `max(today, firstDay)..lastDay`, defaulting to the earliest; gap = `SteppedSlider` 1-14, default `visitEveryDays ?: 7`. Entry: Care banner while away, Settings for an upcoming or current trip.
- **Confirm step**: shown when the trip's latest visit **before today** is still `PLANNED` (a visit on today itself may not have happened yet, and sharing today's list must not flip the screen into its own checklist). All plants ticked; **Continue** calls `QuickLogUseCase.logSitterVisitWaterings(ticked, visitDay)` (WATER logs dated noon of the visit day, never later than now; duplicate guard; no reason, no post-watering reminder, never `onWaterLogged`; the gap touches the trip so slice 2 makes them `AWAY_EXCLUDED`) and then stores `CONFIRMED` with `watered` per plant; **The visit didn't happen** stores `DID_NOT_HAPPEN` and writes nothing. Back / the top-bar arrow = `skipConfirm()`: the visit stays `PLANNED`, nothing is written, and the plan screen follows (the next list assumes it was watered). The state is derived, so confirm is idempotent if the process dies between the logs and the state write.
- **Share** (`PlanVisitViewModel.share(asText)`, under the mutation lock): saves the visit (a same-day `PLANNED` visit has its plants replaced, else a new `PLANNED` visit) and then emits `SharePdf(file, caption)` or `ShareText`. Disabled with nothing listed. The pure `SitterListComposer` (rooms alphabetical case-insensitively, "No room" last, plants by name; species shown only when set and different from the name) feeds two thin renderers over string resources: `SitterListTextRenderer` and `SitterListPdfRenderer` (`PdfDocument`, A4 portrait, laid out from the pure `SitterPdfLayout.paginate`: 3 columns, rows of 190 pt, room headers repeated with "(continued)" across a break, visit pages then **Please don't water these** pages, none when nothing rests). `SitterPhotoLoader` downscales photos while decoding (max 480 px, EXIF-rotated) and opens every stored cover format (`photoUri`: camera/gallery `content://`, `file://`, and the bare absolute path a `.yapt` restore writes, as `file://`); a missing or unreadable photo draws the dashed "No photo" box. Page footer: "Only water the plants on this page" and "Page X of Y".
- **The share file** is `cacheDir/sitter_lists/plant-list-<day>.pdf`, shared through the existing `FileProvider` (`file_paths.xml` `cache-path` `sitter_lists/`) with `ACTION_SEND`, `application/pdf`, `FLAG_GRANT_READ_URI_PERMISSION` + `ClipData`, and an editable `EXTRA_TEXT` caption (`AndroidSitterListOutput.caption`). `SitterShare.newPdfFile` deletes the previous share's files first. It is a cache file, never a photo, so `OrphanPhotoSweeper` (which reads `filesDir`) never sees it.
- **Tests:** unit `SitterRhythmTest`, `VisitProjectorTest`, `BeforeYouLeaveTest`, `SitterListTest` (composer, summary, pagination), `QuickLogUseCaseSitterVisitTest`, `BeforeYouLeaveViewModelTest`, `PlanVisitViewModelTest`, `SitterRhythmViewModelTest`, `SitterListTextRendererTest`, `SitterShareTest` (intent, cache, caption; resets `FileProvider`'s static `sCache` per test), `SitterPhotoLoaderTest` (stored cover formats), `SitterTextTest`; instrumented `SitterRhythmContentTest`, `BeforeYouLeaveContentTest`, `ConfirmVisitContentTest`, `PlanVisitContentTest`, `SitterListPdfRendererTest` (Robolectric has no native `PdfDocument`, so the real PDF is checked on a device), plus the new entry-point cases in `AwayModeSettingsSectionTest` / `AwayModeBannerTest`. Shared fixture: `SitterFlowFixture`.

## Confirming visits after the trip and from Settings (slice 5, #900)
No schema change and no new write path: the sheet is slice 4's `ConfirmVisitContent` unchanged, and the write is slice 4's (`QuickLogUseCase.logSitterVisitWaterings` then the stored state).

- **Offer rule** (`domain/away/VisitConfirmation.kt`, pure): `visitsToConfirmAfterTrip(trips, today)` = `PLANNED` visits that still have plants, of every trip with `lastDay < today <= lastDay + VISIT_CONFIRM_WINDOW_DAYS` (14, adjust in review), sorted by `(day, id)`, i.e. oldest first. A trip still on or upcoming offers nothing (during the trip the Plan screen's own confirm step applies). `CONFIRMED` and `DID_NOT_HAPPEN` visits are never offered again, so "The visit didn't happen" is final. Offering every ended trip still inside its window (not only the latest) is deliberate: a short second trip must not strand the first one's visits.
- **Settings rule**: `settingsVisitTrip(trips, today)` = the current or upcoming trip, else the most recently ended one; `SitterVisit.canConfirmOn(today)` = `PLANNED`, with plants, and `day <= today` (a future visit has nothing to confirm yet; today's can be, since the sitter may already have come).
- **Midnight**: `AwayModeUiState` carries `trips: List<AwayPeriodWithVisits>` (third constructor parameter, default empty) and exposes `visitsToConfirm` / `settingsVisits`; `AwayModeViewModel.uiState` now combines `observeAllWithVisits()` with the existing `dayChange` input, so the prompt appears on the first day back and lapses after the window without a restart.
- **Care prompt**: `AwayModeBannerContent` stacks the trip banner and `VisitsToConfirmPrompt` ("2 sitter visits to confirm", "Starting with the visit on Mon, Oct 6", **Confirm visit**) in one `Column`; the prompt shows with or without the banner. It always opens the oldest visit; answering it advances the prompt to the next.
- **`ConfirmVisitViewModel`** (one instance per Care / Settings destination via `confirmVisitViewModel(app)`): `open(visitId)` / `close()`, `toggleRow`, `confirm()`, `didNotHappen()`, `uiState: StateFlow<PlanVisitUiState.Confirm?>` (`null` while closed, or once the visit is no longer `PLANNED`), `events` reusing `PlanVisitEvent.Confirmed` / `DidNotHappen`. Both answers run under a `Mutex` and re-read the visit from storage inside it, so a double tap or an answer given elsewhere writes once. `ConfirmVisitSheetHost` renders `ConfirmVisitContent` in a `ModalBottomSheet` and reports the result (logged, skipped duplicates) through the host's snackbar; `AwayModeBanner` and `AwayModeSettingsSection` take it as an optional parameter and host the sheet.
- **Settings list**: below the sitter buttons, a "Sitter visits" heading and one row per visit (weekday and day; state "Planned" / "Confirmed" / "Didn't happen" as `stateDescription` and text; plant count, or "1 of 2 plants watered" once confirmed) with **Confirm** for a confirmable visit.
- **Due dates** follow the confirmed waterings with no extra code: the logs are ordinary WATER logs the Care queue already reads.
- Tests: unit `VisitConfirmationTest`, `ConfirmVisitViewModelTest`, `AwayModeViewModelTest` (offer at midnight, answered visit); instrumented cases added to `AwayModeBannerTest` and `AwayModeSettingsSectionTest`.

## Backup (schema v22)
- `BackupRoot.awayPeriods: List<BackupAwayPeriod> = emptyList()`; each trip carries `visits` and their `plants`, with ISO-8601 dates (`LocalDate.toString()`).
- Export reads the three tables once each (bulk) and groups in memory (`buildBackupAwayPeriods`).
- Import runs inside `performImport`'s transaction: `awayPeriodDao().deleteAll()` first, then inserts after the plants. `toRestoredAwayData(restoredPlantIds)` is pure and skips a trip or visit with an unparseable date, re-filters visits into their trip, drops visit plants whose plant is not in the backup, falls back to `PLANNED` for an unknown state, and collapses repeated ids so no insert can violate a key. Plant ids are restored verbatim, so there is no id remapping.

## Learning protection (slice 2, #897)
- **One predicate:** `AwayPeriods.spansAway` drives every exclusion below. Away mode adds no plant-row write and no new caller-snapshot write (#872).
- **Observation** (`AdaptiveWateringObservation`, optional `AwayPeriodRepository`): an away-spanning gap is observed `frozen` with the confidence transition suppressed and no feedback. Base unchanged, `null` confidence stays `null`, one `AWAY_EXCLUDED` row, never `DORMANCY_EXIT` (the exit decrement stays dormancy-only). Label precedence `DORMANCY_EXCLUDED` > `AWAY_EXCLUDED` > `FROZEN_POST_REPOT` > `WATER_NOT_ATTRIBUTED` > feedback triggers. When the history bootstrap wins, the triggering observation still gets its provenance row (dormancy's if both apply). Covers every log written inside a trip, backdated ones, and the first gap that *ends* after a trip; the first gap that *starts* after the last away day learns normally. Details: `rules/care-logging.md`.
- **Feedback strip:** `feedbackForLog()` clears feedback for an away-spanning gap, which also covers Add Care Log edits (`excludeLogId`).
- **Bootstrap:** `CareSchedule.bootstrapBaseInterval(…, isGapExcluded)` generalizes the dormancy filter into one predicate (OR-ed with the plant's dormancy months, which keep their own parameters for existing callers); `WateringLifecycleReset.BootstrapRequest.isGapExcluded` threads it, and the observation passes `spansAway` over the trips it already read.
- **`PlantCareStatus.isWateringGapAwaySpanning`** comes from `computeStatus(…, awayPeriods = emptyList())`; the derived `skipsWateringReasonPrompt` is the single reason-prompt gate for Plant List and Calendar. Plant Detail and Care's "Log watering" picker check the picked date against its own predecessor (`isChosenDateAwaySpanning`, via `evaluateWateringGate()`). **Drop the Calendar gate if #852 removes Calendar.**
- **Plumbing:** the trips flow goes in through `TodayCareRepository` (settings `combine()`, 4 inputs), `PlantListViewModel` (`statusInputs` folds it with the seasonal amplitude to stay at the 5-flow limit), `CalendarViewModel` (5th input) and `PlantDetailViewModel.awayPeriods()` (a suspend read next to `previousWateringBefore`), all via nullable constructor params so existing tests are unchanged; the ViewModel factories take the repository as required.
- **Label:** `WateringAdjustmentTrigger.AWAY_EXCLUDED` ("away — not counted", `adjustment_trigger_away_excluded`), appended last in the enum.
- Tests: `AdaptiveWateringObservationAwayTest`, `QuickLogUseCaseAwayTest`, `CareScheduleAwayTest`, `WateringLifecycleResetAwayTest`, `TodayQueueAggregatorAwayTest`, `TodayCareRepositoryAwayTest`, `PlantListViewModelAwayTest`, `CalendarViewModelAwayTest`, `PlantDetailScreenGateAwayTest`, `EnumResourcesAwayTest`.
